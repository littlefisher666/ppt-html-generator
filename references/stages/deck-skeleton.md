# 全 deck 骨架、目录与导航

## 进入条件

G2 已通过，基础文件已建立。

## 执行

1. 先按 `references/visual-direction.md` 确定整套叙事节奏、每页角色、页面类型、唯一记忆点、主视觉/主要证据、副标题策略、总结条使用情况、母版版式和连续页序；写入 `exports/visual-strategy.md`。统计 `structured`、总结条和 `hero-media` 页面数量并核对重复度规则。
2. 直接复用 `<deck>/templates/` 中的封面、目录、章节、封底及 `slide-shell.html`，不重新编写基础 HTML、CSS
   或导航。内容页此时仅保留母版 chrome、标题、副标题和空 `slide-content` 安全区，须移除静态 shell 中的示例
   正文；页面类型 shell 留待 G6 内容实现时使用。
3. 一次性写入 `assets/deck.js`。`page` 从 1 连续，`href`、数组顺序、文件名前缀一致，标题与可见标题一致。副标题允许为空；空副标题不得以口号式占位文案补齐。
4. 一次性创建所有页面。封面、目录、过渡页（章节页）、封底按母版填充完整内容；内容页只保留母版
   chrome、主标题、副标题和空正文安全区，禁止提前填正文、图片、表格、数据卡或图注。
5. 目录超过 12 项时，创建均分的目录续页：页数为 `ceil(N / 12)`，余数从第一页开始分配。
6. 使用脚手架已复制的 `index.html` 和 `slide.js`；每页加载共享 `deck.js` 后再加载 `slide.js`。不得重新实现导航。

## G3 检查与记录

检查所有基础文件均来自静态脚手架，且只在 `deck.js`、确认的字体 token 和页面安全区内进行任务相关变更。检查 `visual-strategy.md` 包含全部页面且满足页面类型、重复度和主视觉规则。检查目录只显示页码、主标题、副标题；桌面 5 列、中等/小屏 2/1 列。目录链接、首页/上一页/当前页/
下一页、四方向键、首尾页禁用状态和打印隐藏导航均正确。记录到 `exports/deck-skeleton-review.md` 后在
`stage-gates.md` 标记 G3。

后续新增、删除、重排页面，或修改 `deck.js`、目录、共享导航逻辑时，必须回退并重跑本阶段。
