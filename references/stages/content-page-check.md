# 内容页实现与逐页检查

## 进入条件

G5 已通过。必须读取 `exports/visual-strategy.md`、`exports/image-inventory.md` 和 `exports/media-frame-review.md`。

## 执行

仅在此阶段填入内容页正文、表格、数据卡和说明文字。标题、正文、表格、图像必须语义独立；复用共享
class/token，不写页内字号。语义独立不等于必须绘制视觉盒、边框或浅色底。内容留在母版安全区，底部预留
导航 UI；内容页保留标题区、三段横线、Logo。

每完成一个内容页，立即在 1600×900 下执行单页检查并写入
`exports/page-checks/<页码>-<文件名>.md`。未通过不得标记该页完成，不得等待所有页面写完再集中检查。
单页检查通过后，必须按[检查点与恢复](checkpoint-recovery.md)创建该页 G6 检查点，保存页面 HTML、单页
检查记录及媒体依赖哈希；检查点有效后才可勾选该页的单页检查任务。页面级检查点不得保存或恢复共享文件。

## G6 单页检查

1. 截图视觉审看：保存原始尺寸截图，审看并放大正文末行、表格、图注、卡片底栏与导航邻近区。每个文字、
   项目符号、标签、图注和末行必须完整可读，无缺笔画、半行、低对比遮蔽或可见重叠。
2. DOM 几何量测：比较文字及文本后代联合边界与父内容盒，检查 `scrollHeight/clientHeight/overflow`；所有
   可见元素满足 `left ≥ 0`、`top ≥ 0`、`right ≤ 1600`、`bottom ≤ 900`；正文、图表、图片、图注与导航
   可见边界不得相交。
3. 静态扫描：检查 HTML/CSS 的 `overflow: hidden/clip`、`line-clamp`、`text-overflow: ellipsis`、异常固定高度、
   负边距与叠层定位。受众可见文字不得依赖这些规则塞入固定空间。
4. 图片量测：对照清单读取 `naturalWidth × naturalHeight` 和 `getBoundingClientRect()` 渲染尺寸，计算
   `scaleX`、`scaleY`。`|scaleX - scaleY| / max(scaleX, scaleY) ≤ 1%`；渲染图片与媒体框的比例相对源图偏差
   均 ≤ 1%。确认 `object-fit: contain` 或等价实现，未使用 `fill`、`cover`、裁切祖先或负边距隐藏画面。
5. 文本对齐语义检查：按内容的语义角色而非具体文案决定对齐方式。起标识、分类或强调作用的短内容必须
   居中，包括表头、作为分类标签的表格行首列、指标数字及其说明文字组合、流程/步骤节点短名称、并列的
   标签/徽章组，以及卡片或区块标题；需要连续阅读的叙述性内容必须左对齐，包括正文段落、项目符号
   列表、表格中的描述性单元格（非首列）、结论条/说明文字，以及页面主标题和副标题。即：短标签、
   数字、分类名居中；长文本、段落、列表左对齐。媒体容器内与图片配套的标题/说明文字例外：须保持容器
   全宽并居中。
6. 表格列宽检查：设置列宽时，必须确保每列内容，尤其是短标签列，能在单行内完整显示。任一列出现非必要
   换行而其他列仍有可用留白时，必须调整列宽比例；不得以缩小字体或裁切文字代替。记录表格各列宽度、
   发生换行的单元格、调整结果或不适用结论。
7. 中英文混排空格检查：在中文文本中，中文字符与相邻的英文字母、英文缩写、数字或单位之间不得加空格
   （如“AI技术”“20px”“10GB”“20个”“50万元”）；英文内容两侧与中文相邻的空格必须一并删除。逐页
   检查标题、正文、标签、表格、图注和说明文字，并在检查记录中注明结果。
8. 撑满原则检查：逐一检查具有明确布局边界的父容器。父容器有明显剩余空间、其子元素内容较少且未填满
   时，可扩展的子元素必须尽可能扩展以利用该空间，避免留下大片无意空白；适用于流程步骤、标签组、表格、
   KPI 卡片及其他可扩展组件，不因组件类型而例外。固定尺寸的图片、图标等媒体元素按第 10 项媒体居中原则
   处理。仅页面构图中已明确作为视觉策略一部分的有意留白不属于子元素未撑满的容器空间。记录检查结果及
   采取的扩展方式（如增加宽高、均分或拉伸间距）。
9. 同级元素组整体居中检查：当一组同级元素因内容或尺寸约束无法合理撑满父容器宽度时，必须将该组作为
   整体在父容器内水平居中，不得靠左对齐而在右侧留下无意空白；适用于标签组、流程/步骤组、卡片组及其他
   同级元素组。仅视觉策略已明确要求的非居中构图可例外。记录元素组宽度、父容器宽度、水平位置及结论。
10. 媒体居中原则检查：当图片、图标或其他固定尺寸媒体小于其父容器时，媒体元素必须在父容器内水平居中，
   不得靠左对齐；与该媒体配套的标题/说明文字必须保持父容器全宽并居中。记录媒体与父容器的尺寸、水平
   位置及标题/说明文字的宽度和对齐方式。
11. 视觉意图检查：核对页面类型、唯一记忆点、主视觉权重、副标题和总结条使用是否符合
   `visual-strategy.md`。确认没有把每条信息都放入卡片/标签/浅色框，没有无意义的对称排比，且非
   `structured` 页面未退化为等分卡片矩阵。允许有意留白，不得因留白而补入无关文字或容器。

截图视觉结论优先于 DOM 与静态扫描。每页记录逐图源图尺寸、渲染尺寸、媒体框尺寸、缩放比、比例偏差、
`object-fit`、截图结论、三层检查、文本对齐语义检查、表格列宽检查、中英文混排空格检查、撑满原则检查、同级元素组整体居中检查、媒体居中原则检查、视觉意图检查、问题与复测结论；不得只写“图片正常”。

## 并行协作与 G6 门禁

所用 IDE 支持多个 subagent 时，必须按页面分配多个子代理并行检查。子代理只检查分配页面、保存该页记录并报告结果；不得并发修改
`assets/ppt.css`、`assets/deck.js`、`assets/slide.js`、`index.html` 或其他共享文件。共享文件修复由主代理
串行完成，再重测所有受影响页面。

所有内容页通过后运行：

```bash
node scripts/verify-hengda-assets.mjs <deck>/assets/brand --deck <deck>
```

记录固定背景与品牌资源校验结果；共享 CSS、页序或 `deck.js` 改动后重测受影响页面，必要时回退 G3。
若需要将任一页面恢复为 G5 媒体框状态，使用 G5 deck 检查点中该页的 HTML，并按检查点规则使该页 G6
任务和检查记录失效；共享文件已变更时不得进行单页恢复。
