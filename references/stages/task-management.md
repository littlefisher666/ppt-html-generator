# 任务清单管理

本环节贯穿 G1–G7，用于维护 deck 输出根目录的 `tasks.md`，使任务可在中断后从准确的未完成项恢复。
它不替代任何阶段门禁、`exports/stage-gates.md` 或阶段交接产物。

## 执行时机

1. 确认输出目录后、开始 G1 前：创建 `tasks.md`，写入范围与输入、G1–G7 的任务骨架。
2. 每次进入任一阶段前：先读取 `tasks.md`，从第一个未勾选或被取消勾选的项继续，并核对该项的前置条件、
   门禁记录和交接产物。
3. G3 页序确定后：按真实页面创建任务分组。
4. G4 内容和图片清单完成后：按每页实际内容补充、删除或细分任务。
5. 完成、失败、返工或影响范围变化时：立即更新清单。

## 动态拆分规则

`tasks.md` 是动态清单，不是每次原样复制的固定表单。将模板中的尖括号替换为实际值，删除不适用项，并按
页面内容、素材和验收要求增加任务。新增、删除、重排页面或修改内容计划时，必须同步更新清单。

每个内容页必须保留以下可恢复任务类别：内容实现、视觉审看、DOM/静态检查、图片量测（如适用）和单页
检查记录。除此以外，按本页真实工作拆分，而不是用模糊的“完成页面”代替：

- 数据页：增加数据来源、计算口径、图表制作、图例/标签核对等任务。
- 流程或方案页：增加流程图、节点关系、箭头/层级核对等任务。
- 架构或示意页：增加结构图制作、模块关系和说明文字核对等任务。
- 图片页：增加图片准备、图注和展示重点核对等任务；无项目图片时删除图片准备项，图片量测项记录“不适用”。
- 有其他独立可验收的视觉内容时，为其单列制作与核对任务。

修复和复测必须单列。不得把图表、流程图、示意图等不同工作合并为一个 task。

## 勾选与失效

完成一项后，立即将对应 `- [ ]` 改为 `- [x]`，并更新“最后更新”时间。只有该项要求的产物或检查证据已经
落盘时才能勾选；阶段汇总项还必须在关联门禁通过后勾选。不得仅凭聊天结论勾选。

阶段失败、页面返工或共享 CSS、字体、导航、母版资源、页序、`deck.js` 等改动影响既有结果时，立即取消
受影响项的勾选，新增修复/复测项，并按受影响范围重跑阶段门禁。需要文件级恢复时，必须先按
`checkpoint-recovery.md` 归档当前状态，再从检查点恢复；不得通过重新勾选旧任务伪造恢复后的通过状态。
