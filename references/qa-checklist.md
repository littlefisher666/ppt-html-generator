# PPT-compatible HTML 自动验收与修复清单

此清单是 `ppt-html-generator` 的**必经交付环节**。每次新建、生成或改写
`ppt-html/` 后，均须在交付或转 PPT 前执行「母版与资源核对 → 静态扫描 →
运行时量测与交互测试 → 修复 → 回归」。用户不需要另行调用检查技能。

画布：**1600×900（16:9）**；映射：**`pt = px × 0.6`**、
**`px = pt × 5/3`**。不要使用浏览器 96dpi 的 `1pt ≈ 1.333px`。

## 0. 验收环境与范围

- 在逻辑 **1600×900**、无浏览器缩放下验收：
  `html, body, .viewport, .frame, .stage, .slide` 均按设计尺寸量测，
  `transform: none`，舞台 `overflow: hidden`。
- 优先复用项目中的 `scripts/audit-ppt-html.mjs`；没有脚本时，使用浏览器截图
  加 DOM 量测完成同样的检查。只看截图不算完成。
- 检查每一页；共享 CSS、token、字号或 `.dense` 规则改动后，必须全量重测。
- 新增或改动过的局部页面至少重测该页以及所有受到共享样式影响的页面。

### 截图视觉验收优先（不可省略）

- [ ] 为**每一页**输出原始 1600×900（或更高）的渲染截图，并由具备图像查看能力的
  执行者逐页审看；不得只依据静态扫描、DOM 边界、`scrollHeight` 或自动检查的“0 问题”
  结论放行。
- [ ] 先整体审看截图，再对正文密集、底栏紧邻正文、浮层/图形压住文字、细小图注和表格
  单元格等区域放大或裁切审看。缩放后的浏览器预览、被压缩的缩略图不能作为唯一证据。
- [ ] 将截图中的可见信息与 HTML 的作者文案逐项比对：每个 bullet、标签、图注、指标和
  末行文字都应完整可读。文字底部或右侧缺笔画、被横线/色块/图片/遮罩压住、与相邻元素
  叠在一起、只露出半行，均判为视觉失败。
- [ ] 截图判定高于 HTML 几何判定：只要截图有可见遮挡、截断或缺字，即使 DOM 边界、层级
  或自动审计均显示正常，也必须定位根因、修复并重渲染复核。
- [ ] DOM/CSS 检查用于缩小排查范围（父级裁切、z-index、固定高度、网格/flex 压缩等），
  不能穷举所有浏览器渲染、字体度量、透明层与叠层组合，因此不能替代截图视觉判断。

## 1. 静态扫描（先快后准）

在渲染前扫描 HTML 与共享 CSS，发现即修：

- [ ] `font-size` 全部来自声明的 token/角色表；没有页内 `15px`、`17px`、
  `15.5px`、`12.5px` 等魔法值。
- [ ] 每个角色的 `round(px × 0.6)` 符合预定整数 pt（或全 deck 明确采用同一
  半 pt 策略）；正文 ≥12pt（约 20px），图注/脚注 ≥10pt（约 16.67px）。
- [ ] `font-weight` 仅为 400/700；`line-height` 使用 1.2、1.3、1.5 等简单倍率；
  中文正文没有用于“塞字”的细碎字距。
- [ ] `.dense` 通过降低一个 token 档位、缩小 padding/gap 处理密度，未用非法小字。
- [ ] 图片 `object-fit` 与意图一致：架构图/示意图需要完整铺满时为 `fill`；
  可裁切照片为 `cover`；仅在允许留边、必须完整展示时用 `contain`。
- [ ] 枚举 `overflow: hidden` / `overflow: clip`、`line-clamp`、`text-overflow:
  ellipsis` 规则。除已声明为图片裁切的媒体框外，受众可见文字不得依赖这些规则
  “塞进”固定高度；省略号只能用于明确标注为可截断的辅助标签。
- [ ] 没有只设图片宽度、没有高度链，或图片固定高加图注导致父盒被撑破的规则。
- [ ] 所有 `src` / CSS `url()` 都使用项目 `ppt-html/assets/media/`（或项目约定的
  同级统一媒体目录）；恒达母版素材只使用 `assets/hengda/`；没有 `docs/`、绝对路径
  或仓库其他目录的引用。
- [ ] `assets/hengda/template-manifest.json` 存在，清单内 7 个语义化母版素材齐全且
  文件哈希一致；生成结果不依赖或包含原始 PPTX。
- [ ] `assets/media/` 没有缺失引用或未引用的弃用图片；`assets/deck.js` 中页码连续，
  页面顺序、`href`、文件名前缀与实际文件一致。
- [ ] `index.html` 只从 `assets/deck.js` 读取目录数据；每个页面条目只有页码、主标题、
  副标题，没有缩略图、状态、版式名、摘要或备注。
- [ ] `index.html` 在桌面宽度使用 `repeat(3, minmax(0, 1fr))` 或等价 3 列布局；
  中等/小屏仅按 2/1 列降级，桌面不是一行一项。
- [ ] 每页按顺序加载同一份 `assets/deck.js` 和 `assets/slide.js`，没有复制的页间顺序、
  内联键盘处理器或第二套导航脚本。

## 2. 运行时量测（每页必过）

逐页以 1600×900 渲染、截图并量测。正文误差容忍约 3–4px；标题可忽略不超过
8–10px 的字体度量噪声，不能借此忽略真实裁切。

### A. 画布与结构

- [ ] 存在 `.viewport > .frame > .stage > .slide` 或等价的固定 1600×900 舞台。
- [ ] `.slide` 画布内没有元素越界：`bottom ≤ 900`、`right ≤ 1600`。
- [ ] 关键文字距装饰框内缘保留约 20–28px 安全区；页脚/页码在画布内且不和主内容相交。
- [ ] 恒达内容页保留右上彩色 Logo、三段母版横线、标题区和正文安全区；封面、目录、
  章节、封底使用各自对应的母版素材与 Logo 版本，而不是仅套相似配色。
- [ ] 封面标题允许换行且在母版标题框内底对齐；最后一行底部距 `y=461.4px` 横线约
  8–16px，没有因固定顶对齐产生大空隙。
- [ ] 目录页保持母版版式级的浅蓝到白色纵向渐变；顶部合成色约为 `#DDEAF9`，底部为
  `#FFFFFF`。OOXML 中标记 `hidden="1"` 的焊接图、白色前景渐变和蓝色前景渐变均未
  被错误显示。左侧竖排 `CONTENTS` 与“目—圆形箭头—录”组合完整；圆、两个汉字共用
  同一垂直中心轴，汉字在圆形符号上下间距对称；圆内是向右的等边三角形，三角形包围盒
  与圆在水平和垂直两个方向都严格居中。右侧
  条目起点、6 行节奏、75.59px 圆角数字方块与渐隐条目样式一致；没有自创左右分栏标题区、
  圆形编号或目录卡片，也没有让两个汉字脱离共同标题容器自由定位。
- [ ] 内容页三段横线坐标和尺寸与母版一致，且渐隐长线在底、深蓝线在中、浅蓝线在顶；
  重叠区的深蓝线未被渐隐线冲淡。
- [ ] 底部导航水平居中且完整位于画布内；其可见边界不与正文、页脚、Logo 或关键素材相交。
- [ ] 布局不依赖“浏览器窗口刚好够大”才不溢出。

### B. 文字裁切、重叠与密集内容

- [ ] 以截图为准检查所有可读文字是否完整：不能有被任意元素遮住的下沿/右沿、残缺字形、
  看似存在但不可辨识的文字，或被背景/透明层降低到无法阅读的正文。此项不限定根因；
  即使不存在 `overflow`、`line-clamp` 或 DOM 越界，也必须报告并修复。
- [ ] 文本节点不越出父盒；`scrollHeight ≤ clientHeight + 阈值`，没有被
  `overflow: hidden` 或固定行高掩盖的内容。此检查不能只量测文字自身：对每个
  非媒体的 `overflow: hidden` / `clip` 祖先容器，比较其全部可见文本后代的联合
  边界与内容盒，任一后代超出内容盒 >2px 即报 `ancestor-clip`。
- [ ] 没有 `line-clamp` 加不足行高造成的半截中文，列表 `li` 未被错误压成过小的
  flex 子项；`ul` / `ol` / `.bullets` 也要单独量测，避免最后一个完整的 `li` 被
  父级裁掉而其自身 `scrollHeight` 仍正常。
- [ ] 对“标题 + 正文列表 + 底部指标/foot”的密集卡，逐卡核对：DOM 中的项目符号数
  与截图中完整可见的项目数一致，最后一项底边必须在 `.foot`、指标条或分隔线之前。
  若不足，增加卡/行高度、重分配 flex/grid 或缩短文案；不得以隐藏溢出、clamp 或
  更小字号掩盖。
- [ ] 主内容矩形不与 `.footer` 相交；标题、指标、表格、chip/tag 之间没有重叠。
- [ ] 问题/措施/结果等均分行能容纳最长文案：两行时 `min-height` 至少容纳
  `2 × line-height + padding`；表格单元格没有半截字。
- [ ] 「标签列 + 正文列」中，标签列足以容纳最长标签（如 5 字标签约 `7em+`），
  `nowrap` 不会侵入正文，列间距或分隔线清晰。
- [ ] 信息过密页通过删减文案、重分配网格/flex 或增加区域高度解决；不以更小非法字号、
  全局隐藏溢出或只截图作为“修复”。

### C. 多栏、等卡与底边对齐

- [ ] 同级双栏/多栏的 top 与 height 一致，外框 bottom 差 ≤1px；左右底部主卡或
  说明条也对齐。
- [ ] 等卡网格外框等高，图片区等高；标题 Y、正文 Y、底栏 Y 一致。优先用固定图片
  比例和 grid 行轨，不让长短文案改变对齐基线。
- [ ] 使用 `height: 100%`、`flex: 1` 或等价伸展让应铺满的栏位铺满；排查 `.dense`
  是否把 `.grow` 误改为 `flex: 0 1 auto`。
- [ ] 图文卡使用列 flex：容器 `height: 100%`，图片 `flex: 1; min-height: 0`，
  图注占固定空间；图和图注总高不超过父容器。

### D. 图片策略与资源

- [ ] 架构图/示意图若原意为“整图铺满”，保持 `fill`，不得擅自改为 `contain`；
  若被裁切，排查是否误用 `cover`。
- [ ] 照片特写需要铺满时使用 `cover`；需要完整可见时才使用 `contain`，并接受留边。
- [ ] 所有新增图先放入 `assets/media/` 再引用；弃用图同时删除引用和文件。
- [ ] 媒体引用集合与文件集合一致，CSS 内的背景图同样受此约束。

### E. 空白与内容分配

- [ ] 主栏内容 bottom 与栏 bottom 的间隙通常 ≤8–12px；因排版意图保留的空白需合理且
  明确，不能出现改字号后 >100px 的无意义底空。
- [ ] 下方媒体区或卡片能够用 `flex` 吃掉剩余空间，不因锁死过小高度（如 130px）而
  上紧下空。
- [ ] 文案较少时，卡片不因 `justify-content: center` 而显得悬空；改为 `flex-start`
  或调整 flex 分配。
- [ ] 卡片间 gap 均匀（通常 ≥8–12px），文本密集卡预留约一行的 wrap 余量，固定模块
  以最长预期文案和最大角色 token 定尺寸。

### F. 一致性与可转 PPT 性

- [ ] 同一角色跨页字号一致，颜色与共享 palette 一致，页脚名称与页码一致；封面、章节、
  内容、结束页复用统一模式。
- [ ] 标题、正文、页脚具备清晰 DOM 语义；表格是真实 grid/table，而非绝对定位的文字碎片。
- [ ] 若需要可编辑 PPT，已记录 `pt = round(px × 0.6)`、`inch = px / 120`；字体有可用
  的 PPT 替代或嵌入方案；关键语义未只依赖复杂 CSS 滤镜、遮罩或文本渐变。

### G. 目录与导航交互

- [ ] `index.html` 的条目数与 `assets/deck.js` 页数相同；逐项核对页码、主标题、
  副标题和链接目标，没有缺页、重复页、孤立页面或死链。
- [ ] 桌面视口第一行恰好显示 3 个目录项；宽度降至 1080px 以下为 2 列，720px 以下
  为 1 列，所有卡片文字仍完整可读。
- [ ] 每个页面底部中间显示“首页 / 上一页 / 当前页 / 下一页”，当前页与总页数正确；
  第一页的上一页禁用，最后一页的下一页禁用，其余链接逐页可达。
- [ ] `ArrowLeft`、`ArrowUp` 均进入上一页；`ArrowRight`、`ArrowDown` 均进入下一页。
  在第一页/最后一页不会越界，也不会生成不存在的文件地址。
- [ ] 焦点位于 `input`、`textarea`、`select` 或 `contenteditable` 时不劫持方向键；
  `Alt/Ctrl/Meta/Shift` 组合键不触发翻页。
- [ ] 首页按钮回到 deck 根目录的 `index.html`；从目录进入任意页后，上一页/下一页的
  相对路径仍正确，不会出现 `slides/slides/`。
- [ ] 导航链接有可见焦点、禁用状态和可访问名称；`@media print` 或导出样式中
  `[data-ppt-ui]` / `.slide-nav` 被隐藏，不进入 PPT 页面。

## 3. 修复与回归顺序

按下列优先级处理，修复后立即复测受影响页面：

1. 出画布、导航/页脚/正文重叠。
2. 半截文字、父容器裁切的列表、措施/标签粘连、表格溢出。
3. 恒达母版 chrome、版式素材、Logo 或目录/导航顺序错误。
4. 双栏或等卡不对齐。
5. 图片被误裁、未按原意铺满或图文容器溢出。
6. 异常底空与内容没有撑满。
7. 媒体路径、缺失资源和弃用资源。

常用修复是增高行/卡、缩短文案、用 `minmax(0, 1fr)` 重分配网格、加宽标签列、
取消错误 clamp、恢复必要的 `flex: 1`。若卡片有底部指标条，先为指标条保留固定行高，
再以最长正文验证列表区；禁止以非法小字号、任意像素微调或隐藏溢出替代修复。

任何全局或局部字号上调后，必须重新执行本清单的 B–E，尤其检查 dense 页、等分行、
固定 flex 区和底栏。改动 `ppt.css`、token 或共享布局规则后必须全 deck 回归。

## 4. 交付门槛与报告

只有满足以下条件，才能声明 deck 完成：

- [ ] 全页无出画布、未解释的文字裁切或页脚碰撞。
- [ ] 双栏/多栏底边差 ≤1px；等卡关键基线对齐。
- [ ] 图片的 `fill` / `cover` / `contain` 符合内容意图，且全部来自统一媒体目录。
- [ ] 恒达内置素材 manifest 校验通过，7 个母版素材齐全，母版 chrome 与各版式对应素材
  使用正确，输出中没有原始 PPTX。
- [ ] 目录项数/顺序/元数据与 `deck.js` 一致，逐页点击和四方向键翻页全部通过。
- [ ] 无异常大底空，字号、字重、行高仍在 token 体系内。
- [ ] 静态扫描、运行时量测和必要回归已经完成；截图可存于
  `ppt-html/exports/audit-*/`。

交付时报告：页数、通过/已修/阻塞状态、逐页问题和处理、media 对账结果、外部路径数，
以及可用的截图目录。若还有阻塞，必须写明页码、证据和需要用户决定的事项。

## 5. 视觉抽查

逐页截图视觉验收是必做项；下列页面是额外的重点复核，不能替代全页审看：封面、一页
密集表格/时间线、一页双栏内容页、一页含“列表 + 底栏/指标条”的密集卡和结束页。关注
截断、任意叠层遮盖、父容器裁切、碰撞、弱对比、卡片 gap 和视觉重心。
